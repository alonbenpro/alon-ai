# L05 private operator access

The L05 API denies every route except `/health/live`, `/health/ready`, `/auth/login`, and idempotent `/auth/logout` without a current server-verified operator session. Sessions use an HMAC-signed, HttpOnly, SameSite=Lax cookie and a guarded PostgreSQL session record; logout revokes an active record and clears the browser cookie even if the session has already expired. Mutating requests require the configured frontend origin. The Next.js shell forwards the cookie through same-origin route handlers and never treats browser state as command authority.
Failed password checks run off the async event loop under a database-serialized, five-attempt/15-minute limit. Login validation errors never echo submitted credentials.

After applying migrations, configure `ALON_AI_OPERATOR_AUTH_SUBJECT` with the one operator's stable subject, `ALON_AI_OPERATOR_PASSWORD_HASH` with a salted scrypt verifier produced by `alon_ai.api.auth.hash_password()`, and `ALON_AI_SESSION_SIGNING_KEY` with at least 32 random bytes. Generate the verifier interactively (for example, call `hash_password(getpass())` in a trusted local Python process) and generate the signing key with a cryptographic random generator. Supply both through deployment secret injection; do not put them in tracked files, shell history, or logs. From the `backend` directory, run `uv run python ../scripts/provision_operator.py --display-name Alon` to bind the configured subject to the existing `record_operators` table. The command is idempotent for the same active subject and refuses a second active operator. Production API startup fails when authentication configuration is absent or the signing key is too short. Rotate the signing key to invalidate all outstanding cookies; revocation remains recorded in PostgreSQL.

The authenticated `/operator/status` and `/operator/activity` routes project only governed call identifiers, operation kinds, timestamps and authoritative states. They never expose provider requests, evidence text, recipients, or secrets. `/operator/activity/events` emits the same read-only sanitized projection and rechecks the session while connected. The frontend falls back to polling when the live stream is unavailable.
